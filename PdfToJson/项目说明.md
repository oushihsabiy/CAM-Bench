# mathdoc-parser 项目说明

> 更新日期：2026-04-17

---

## 1. 项目定位

mathdoc-parser 是一个面向数学教材 PDF 的 **端到端自动结构化流水线**。它将数学教材 PDF 转换为可用于 Lean 形式化的结构化 JSON 数据，涵盖从 OCR 到最终审核的完整链条。

当前仅支持 `book` 模式（教科书版式）。

目标产物是：经过依赖展开、自然语言标准化、LLM 审核后的数学习题 / 定理结构化记录，可直接用于后续 Lean 4 形式化流水线（如 JSON2LEAN 项目）的消费。

---

## 2. 完整流水线总览

```
PDF
 │
 ▼  Stage 1: OCR
Markdown (.md)  ──  带 <!-- PAGE n --> 标记
 │
 ▼  Stage 2: 语义分块 + LaTeX 化
LaTeX (.tex)    ──  带 %<BLOCK> 标记
 │
 ▼  Stage 3: 结构化提取
JSON (.json)    ──  每条 = 一道题/定理，含依赖链
 │
 ▼  Stage 4: 自然化
Naturalized JSON ── 加入 problem_standardized_math, problem_finally
 │
 ▼  Stage 5: LLM 审核
Reviewlog JSON   ── 每条含 overall_status + issue_type 诊断
 │
 ▼  Stage 6: 分拣
accept / hold / revise  ──  按 overall_status 分到三个目录
 │
 ▼  (可选) Stage 7: 修复流水线 (revise-only)
Repair → Re-review → Re-summary
 │
 ▼  (可选) Stage 8: Hold 修复流水线 (hold-only)
Repair-hold → Review-hold → Re-summary
```

---

## 3. 入口脚本与调用关系

### 3.1 主入口：`main.py`

`main.py` 是整条流水线的编排器，做以下事情：

1. 读取 `settings.json` 获取所有配置项。
2. 扫描 `input_pdfs/book/**/*.pdf`，计算哪些 PDF 需要处理（支持断点续跑）。
3. 对每个 PDF 依次执行 Stage 1 → 2 → 3 → 4 → 5，每个阶段以子进程方式调用对应 Python 脚本。
4. 支持原子写入（先写 `.tmp` 再 rename）和严格完整性校验。

子进程代理环境变量会被自动清除，避免 SDK 报错。

### 3.2 独立入口

| 入口 | 功能 |
|------|------|
| `src/review/summary.py --review-only` | 仅跑 review + summary，不重跑上游 |
| `src/review/summary.py --summary-only` | 仅按已有 reviewlog 分拣，不调 LLM |
| `src/review/repair_run.py --revise-only` | 独立 revise 修复流水线（Repair → Review → Summary） |
| `src/review/hold_run.py --hold-only` | 独立 hold 修复流水线（Repair-hold → Review-hold → Summary） |
| `src/review/read.py` | 单独跑 review（不联动 summary） |
| `src/review/repair.py` | 单独跑 repair（不联动后续 review/summary） |
| `src/review/repair_hold.py` | 单独跑 hold repair（过滤 missing_dependency，输出 `-re3`） |
| `src/review/reviewchat.py` | 单独重建 reviewchat 汇总表格 |

## 4. 各阶段详细说明

### 4.1 Stage 1: PDF → Markdown（OCR）

**脚本**：`src/book/pdfTomd.py`

**功能**：
- 逐页将 PDF 渲染为图片，通过 OpenAI vision API 做 OCR。
- 每页输出以 `<!-- PAGE n -->` 标记分隔。
- 内置 OCR 质量评估：检测空页、prompt 泄露、重复行、数学公式退化。
- 多候选评分机制：对同一页生成两个候选，选评分更高的。
- 后处理标准化：统一 `**Exercise x.y**` 格式、标准化 Solution 标题。

**关键配置**（`src/book/settings.json`）：

| 配置项 | 说明 |
|--------|------|
| `OCR_DPI` | 渲染 DPI（默认 450） |
| `OCR_WORKERS` | 并发 OCR 工作线程数 |
| `OCR_API_CONCURRENCY` | API 并发请求数 |
| `OCR_TIMEOUT` | 单次请求超时（秒） |
| `OCR_PAD_TOP` / `OCR_PAD_OTHER` / `OCR_PAD_MAX_PX` | 页面边距填充参数 |
| `OCR_UPLOAD_FMT` / `OCR_UPLOAD_JPEG_QUALITY` | 上传图片格式与质量 |

**输入**：单个 PDF 文件路径
**输出**：带 `<!-- PAGE n -->` 标记的 Markdown 文件

---

### 4.2 Stage 2: Markdown → LaTeX

**脚本**：`src/book/mdTotex.py`

**功能**：
- 将 OCR Markdown 转为语义化 LaTeX。
- 核心能力：**页级 tag 恢复** —— 对比 Markdown 与 PDF 原文，找出 OCR 遗漏的 `\tag{}`。
- 支持多页并发处理。
- 去重安全检查：确保恢复的 tag 不与已有 tag 冲突。

**关键配置**：

| 配置项 | 说明 |
|--------|------|
| `MDTOTEX_WORKERS` | 并发处理线程数 |
| `MDTOTEX_MAX_TOKENS` | LLM 最大 token 数 |
| `MDTOTEX_MAX_TOKENS_TAG` | tag 恢复 LLM 最大 token 数 |
| `MDTOTEX_SKIP_TAG_RECOVERY` | 跳过 tag 恢复（主 `settings.json`） |

---

### 4.3 Stage 3: LaTeX → JSON

**脚本**：`src/book/texTojson.py`

**功能**：
这是整条流水线最核心的脚本，负责从结构化 LaTeX 中提取数学题目和定理记录。

主要能力：
- **块解析**：从 `%<BLOCK>` 标记提取习题、定理、引理、定义、推论等。
- **类型推断**：基于规则判断题目类型（证明题 / 求值题 / 其他）。
- **依赖追踪**：
  - 一级依赖（body_refs, theorem_refs）：题目直接引用的公式和定理。
  - 二级依赖（expanded_*）：一级依赖中引用的公式和定理。
  - 三级依赖（third_*）：二级依赖中引用的公式和定理。
  - 递归依赖（more_*）：三级之后的递归展开（需开启 `--recursive-more`）。
- **problem 清洗**：可选 LLM 清洗去除 hint / 废话 / 教学性描述，输出 `problem_clean` 字段。
- **问题上下文拼接**：将依赖内容拼接进 `problem_with_context`，供后续自然化使用。
- **LLM 自检修复**：可选 iterative self-repair 循环。
- **直接答案提取**：对求值题提取 `direct_answer` 字段。

**每条 JSON 记录的核心字段**：

| 字段 | 说明 |
|------|------|
| `index` | 连续编号（从 1 开始） |
| `problem` | 原始题干（清洗前） |
| `problem_clean` | 清洗后题干（去除 hint、废话等） |
| `proof` | 证明文本 |
| `direct_answer` | 直接答案（求值题） |
| `题目类型` | `["证明题"]` / `["求值题"]` / `["其他"]` |
| `source` | 来源名称 |
| `source_idx` | 题号，如 `Exercise 2.3` |
| `problem_with_context` | 拼接了所有依赖上下文的完整题目 |
| `body_refs` / `theorem_refs` | 一级公式 / 定理引用 |
| `expanded_*` / `third_*` / `more_*` | 二级 / 三级 / 递归依赖 |
| `dependency` | 紧凑格式的依赖信息 |

**关键配置**（`src/book/settings.json`）：

| 配置项 | 说明 |
|--------|------|
| `TEXTOJSON_REFINE_MODE` | 类型精化模式（`off` / `rule`） |
| `TEXTOJSON_IMPLICIT_DEPS` | 隐式依赖推断（`off` / `rule`） |
| `TEXTOJSON_GEN_MISSING_PROOFS` | 自动为缺失证明的定理生成空证明 |

---

### 4.5 Stage 4: Naturalize（自然化）

**脚本**：`src/book/jsonNaturalize.py`

**功能**：
对 Stage 3 输出的 JSON 做 LLM 驱动的自然语言标准化，使题目表述适合 Lean 形式化。

两步流程：
1. **依赖折叠 + 完整化**（prompt: `src/prompts/make_problem_complete.md`）：
   - 将 `problem_with_context` 中的依赖引用逐层折叠进正文。
   - 补充缺失的定义、条件、假设。
   - 输出 `problem_standardized_math` 字段。
2. **精简重写**（prompt: `src/prompts/make_problem_concise.md`）：
   - 去除冗余叙述、hint、等价改写。
   - 保持形式化所需的所有条件。
   - 输出 `problem_finally` 字段。

**新增字段**：

| 字段 | 说明 |
|------|------|
| `problem_standardized_math` | 依赖折叠后的标准化表述 |
| `problem_finally` | 最终精简表述（形式化目标） |
| `naturalize_status` | 状态：`ok` / `fallback_original` / `fallback_context` / `skipped` / `failed` |
| `naturalize_prompt_version` | 使用的 prompt 版本 |

**关键配置**（`settings.json`）：

| 配置项 | 说明 |
|--------|------|
| `ENABLE_NATURALIZE` | 总开关 |
| `NATURALIZE_MODEL` | 使用的 LLM 模型 |
| `NATURALIZE_MAX_TOKENS` | 每次 LLM 调用 token 上限 |
| `NATURALIZE_MAX_ITEMS` | 每文件处理的最大条数（0 = 全部） |
| `NATURALIZE_FORCE` | 强制重跑已有结果 |

---

### 4.6 Stage 5: Review（LLM 审核）

**脚本**：`src/review/read.py`（批量编排）+ `src/review/review.py`（单条审核）

**功能**：
对每条 naturalized JSON 记录，调用 LLM 进行四维审核：

| 审核维度 | issue_type | 含义 |
|---------|-----------|------|
| 假设保持 | `missing_assumption` | `problem_finally` 丢失了原题的假设？ |
| 任务保持 | `task_drift` | 数学任务发生了非等价变化？ |
| 自包含性 | `missing_dependency` | 引用了未说明的 tag / 定理 / 算法？ |
| 定义完整性 | `missing_def` | 使用了未定义的专业术语或符号？ |

额外判断：
- 如果 `problem_finally` 含 `formulate` / `compute` 等不适合形式化的动词 → `hold`
- 如果引用了 `Theorem X.Y` / `Alg. X.Y` / `part (b)` 但未解释 → `missing_dependency` → `hold`
- 如果使用了 `ill-conditioned` / `L(x,y)` 等未定义的专业术语 → `missing_def` → `revise`

**输出**：每条记录一个审核报告 JSON，包含：
- `overall_status`：`accept` / `revise` / `hold`
- `issue_type`：四维诊断详情（value + reason + suggestion_fix）
- `confidence`：0–1 置信度
- `reason`：整体判定理由

**审核 prompt**：
- 默认：`src/prompts/review.md`
- hold-only 复审：`src/prompts/review_hold.md`

**关键配置**（`settings.json`）：

| 配置项 | 说明 |
|--------|------|
| `ENABLE_REVIEW` | 总开关 |
| `REVIEW_MODEL` | 使用的 LLM 模型 |
| `REVIEW_MAX_TOKENS` | 每次 LLM 调用 token 上限 |
| `REVIEW_LLM_RETRIES` | 重试次数 |

---

### 4.7 Stage 6: Summary（分拣 + 汇总）

**脚本**：`src/review/summary.py`

**功能**：
1. 按 `overall_status` 将同一输入文件的记录分为三类输出：
   - `accept` → `output_review/accept/...`
   - `hold` → `output_review/hold/...`
   - `revise` → `output_review/revise/...`
2. 分拣后每个输出文件的 `index` 从 1 连续重编号。
3. 自动更新 reviewchat 汇总表格。

**Reviewchat 表格**（`src/review/reviewchat.py`）：
- 按文件名 prefix 聚合。
- 同一 prefix 的 round1/round2/round3 显示在同一文件中。
- 输出到 `output_review/reviewchat/<prefix>/`：
  - `table.md`（chat1+chat2+chat3）
  - `table.json`
  - `table.csv`（chat1）
  - `table_chat2.csv`（revise reason）
  - `table_chat3.csv`（hold reason）

其中：
- chat1：`round1_origin`、`round2_revise`、`round3_hold(except missing_dependency)`
- chat2：`missing_assumption/task_drift/missing_def`
- chat3：`missing_dependency/unsuitable_lean/parse_error`

---

### 4.8 Stage 7: Repair（修复流水线，可选）

**入口**：`src/review/repair_run.py --revise-only`

针对 Stage 6 分出的 `revise` 文件，执行三步独立流水线：

1. **Repair**（`src/review/repair.py`）：
   - 根据审核报告中的 `value_true_issues` 和 `suggestion_fix`，调用 LLM 重写 `problem_finally`。
   - 输入：`output_review/revise/book/`
   - 输出：`output_review/revise/rewrite/`
   - Prompt：`src/prompts/repair.md`

2. **Re-review**（`src/review/read.py`）：
   - 对修复后的结果再次 LLM 审核。
   - 输出：`output_review/revise/reviewlog/`

3. **Re-summary**（`src/review/summary.py --summary-only`）：
   - 按第二轮审核结果分拣到 `output_review/revise/split/`。
   - 同时更新 reviewchat 表格的 `round2(re2)` 行。

该流程与主流程输出目录完全隔离，不互相覆盖。

### 4.9 Stage 8: Hold Repair（修复流水线，可选）

**入口**：`src/review/hold_run.py --hold-only`

针对 Stage 6 分出的 `hold` 文件，执行独立三步流水线（与 revise 隔离）：

1. **Repair-hold**（`src/review/repair_hold.py`）：
   - 过滤 `missing_dependency=true` 条目，仅处理可修复 hold。
   - 输出文件名自动加后缀 `-re3`。
   - 输入：`output_review/hold/book/`
   - 输出：`output_review/hold/rewrite/`
   - Prompt：`src/prompts/repair_hold.md`

2. **Review-hold**（`src/review/read.py --prompt-path review_hold.md`）：
   - 对 hold 修复结果进行专用复审。
   - 输出：`output_review/hold/reviewlog/`
   - Prompt：`src/prompts/review_hold.md`

3. **Re-summary**（`src/review/summary.py --summary-only`）：
   - 输出到 `output_review/hold/split/`。
   - 同时更新 reviewchat 的 round3 行与原因统计表。

## 7. 断点续跑与容错

`main.py` 内置了完善的断点续跑和容错机制：

1. **阶段完整性校验**：每个阶段完成后检查输出是否完整（MD 检查 PAGE 标记 vs PDF 总页数，TEX 检查 `\begin{document}` / `\end{document}`，JSON 检查是否为非空 list/dict）。
2. **跳过已完成阶段**：如果某阶段的输出已存在且通过完整性校验，直接跳过。
3. **原子写入**：`ATOMIC_OUTPUTS=true` 时先写 `.tmp` 再 rename，防止中途崩溃产生半成品。
4. **陈旧 tmp 清理**：`CLEAN_STALE_TMPS=true` 时自动清理上次崩溃留下的 `.tmp` 文件。
5. **严格模式**：`STRICT_RESUME=true` 时对 MD/TEX/JSON 做较严格的完整性检查；关闭则仅检查文件非空。
6. **ONLY_THESE_STEMS 过滤**：可在 `settings.json` 指定只处理特定 PDF，支持 stem 名、相对路径、目录前缀匹配。

## 8. Token 用量日志

`src/token_usage.py` 为所有 LLM 调用提供统一的 token 用量日志功能。

- 真实用量（API 返回）写入 `token_usage_real.jsonl`。
- 估算用量（无 API 返回时回退）写入 `token_usage_estimated.jsonl`。
- 每条日志包含：`call_id`、`timestamp`、`model`、`base_url`、`prompt_tokens`、`completion_tokens`、`total_tokens`、`script` 等字段。

## 9. Prompt 体系

所有 LLM prompt 均外置于 `src/prompts/` 目录，由代码在运行时读取注入。

| Prompt 文件 | 用途 | 使用阶段 |
|------------|------|---------|
| `clean_problem.md` | 清洗题目文本：去除 hint、废话、教学性描述，保留数学内容 | Stage 3 (texTojson) |
| `make_problem_complete.md` | 依赖折叠 + 条件补全：生成 `problem_standardized_math` | Stage 4 (jsonNaturalize) |
| `make_problem_concise.md` | 精简重写：生成 `problem_finally` | Stage 4 (jsonNaturalize) |
| `review.md` | 四维审核：检查假设保持、任务漂移、依赖缺失、定义缺失 | Stage 5 (review) |
| `repair.md` | 根据审核意见修复 `problem_finally` | Stage 7 (repair) |
| `review_hold.md` | hold 复审（round3 专用） | Stage 8 (review-hold) |
| `repair_hold.md` | hold 修复（严格等价改写 `problem_finally`） | Stage 8 (repair-hold) |

## 10. 数据流转示例

以处理 `input_pdfs/book/Nocedal_Wright.pdf` 为例：

```
input_pdfs/book/Nocedal_Wright.pdf
    ↓ pdfTomd.py
work/book/Nocedal_Wright/Nocedal_Wright.md
    ↓ mdTotex.py
work/book/Nocedal_Wright/Nocedal_Wright.tex
    ↓ texTojson.py
output_json/book/Nocedal_Wright.json          (N 条记录)
    ↓ jsonNaturalize.py
output_json_naturalized/book/Nocedal_Wright.json  (N 条, +problem_standardized_math, +problem_finally)
    ↓ read.py + review.py
output_review/reviewlog/book/Nocedal_Wright.json  (N 条审核报告)
    ↓ summary.py
output_review/accept/book/Nocedal_Wright.json     (accept 子集)
output_review/hold/book/Nocedal_Wright.json        (hold 子集)
output_review/revise/book/Nocedal_Wright.json      (revise 子集)
output_review/reviewchat/Nocedal_Wright/table.md   (汇总表格)
```

---

## 11. 运行建议

1. **日常全量跑**：`python main.py`
2. **仅补 review + summary**：`python src/review/summary.py --review-only`
3. **修复 revise 条目**：`python src/review/repair_run.py --revise-only`
4. **修复 hold 条目**：`python src/review/hold_run.py --hold-only`
5. **报表自动维护**：summary 完成后会自动更新 reviewchat 三表（chat1/chat2/chat3）；如需全量重建可运行 `src/review/reviewchat.py`。
5. **查看完整命令示例**：参见 `命令.md`。
