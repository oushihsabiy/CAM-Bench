# Pipeline整理（JSON2LEAN）

---

## 主体流程

- 预处理 ：从PDF2JSON的生成文件中读取题目完整，self-contained 的json格式习题（均为证明题），对文件进行条目化处理。

- 翻译 + 编译修复 ：根据json_to_lean.md 作为翻译的prompt对json文件进行逐block的翻译，根据lake env lean生成的报错信息以及compiling_fixer.md作为prompt进行编译修复。（均接MCP）

- “语义审查 + 语义修复 + 编译修复”循环  ：以每个json block为一个单元，根据semantic_review.md 作为prompt进行语义审查，拿生成的语义报告以及semantic_rewrite.md作为prompt进行语义修复，修复后进行编译修复，然后再进行语义审查循环，直至语义审查和编译修复均通过为止。（均接MCP）

- 整合输出 ：一个章节为一个lean文件，一道题目为一个section。

- 后处理：优化注释渲染，去除lean代码冗余部分。优化mathlib接口（还没写）

- utils: 生成失败报告；收集运行过程中所有编译错误进行汇总，可以运行error_analyzer.py来提取出现频率较高的错误

## 创新点

- ### 预处理

```
原始题目文本

│

▼

Stage 0a: 提示语提取（hint extraction）

│ → hints 记录 + 占位符替换

▼

Stage 0b: 特殊块提取（special-block extraction）

│ → opt_prob / algo 记录（带命名）+ 占位符替换

▼

Stage 1: 定义提取（definition extraction）

│ → defn 记录（仅优化领域术语，不修改原文）

▼

Stage 2: 定理构造（theorem construction）

│ → thm 记录（占位符替换 + 自然语言修复）

▼

Stage 3（可选）: 归一化（normalization）

│ → 全部记录统一为标准数学英语

▼

输出: List[FlatRecord] → JSON 文件
```

##### 为什么要这样做：

- 相较于教材正文，习题的结构会更加复杂，人为的提取出一些语义块，能够使结构更加清晰。

- 进行编译修复和语义修复时可逐块处理，减轻llm修复负担。

##### 创新点：

- 语义块提取

- 占位符替换与恢复 



- ### 历史信息（repair_history）

##### 为什么要这样做：

- 编译修复或语义修复时，如果没有历史信息，可能会来回犯同样的错误。

##### 具体实现：

- 在“翻译+编译修复”流程中，在编译修复过程中添加当前block历史修复记录（保留近5次），防止llm修复时犯历史错误。

- 在“语义审查 + 语义修复 + 编译修复”流程中，对当前block添加编译修复和语义修复的历史记录，防止llm修复编译错误时，为了修复正确犯历史语义错误；同理防止llm修复语义修复时，为了修复正确犯历史编译错误（保留近5次）

- 修复的时候会带着语义检查报告和修复历史进行，并且设有有语义检查机制驳回，来尽量确保每一次修复错误的时候不会把语义减弱，进一步确保每一次修复都是保证语义进一步贴合而非单纯追求通过编译的目标。


- ### 局部patch策略

#### 具体实现
- 修改的时候采取局部patch策略,给大模型当前section已经修改正确的前文内容作为上下文，冻结其他部分的内容，并在返回时只merge当前block的内容。

#### 为什么这样做

- 避免改动其他正确的内容，同时减少prompt和tokens

- 可以渐进地让一整道题都实现语义对齐

- 如果只是每一个block独立地语义对齐，不一定代表整道题语义对齐
